# Bugfix Spec: объявление без цены и снятое объявление ломают оценку

- **Slug:** `predict-edge-listings`
- **Тип:** Bugfix Spec, проведён как Quick Spec (владелец 2026-09-23: «Исправь все баги»,
  баги перечислены ему в разборе красного смоука)
- **Заведено:** 2026-09-23

## 1. Current behavior (как есть)

**A. Объявление без цены («договорная»).** Парсер отдаёт `price=None`
([detail_parser.py:103](../../../src/krisha/scraping/detail_parser.py) —
`int(adv["price"]) if adv.get("price") else None`). Карточка строит признаки через
`listing_to_frame` → `build_features`, а там `df["log_price"] = np.log1p(df["price"])`:
на колонке из одного `None` (dtype object) это `TypeError: loop of ufunc does not
support argument 0 of type NoneType` — проверено на реальной странице из
`tests/fixtures/detail_sample.html` с `price=None`. `TypeError` не ловит ни одна ветка
`/api/predict` → **500 Internal Server Error**; бот ловит только `ValueError/RuntimeError`,
остальное глотает `_process_tg_update` — **пользователь бота не получает ответа**. При
этом весь путь ниже к «без цены» готов: схема `actual_price: int | None`, вердикт `None`,
`format_reply` бота, экран `VERD.NO_PRICE` на фронте — до них просто не доходит.

**B. Снятое объявление (krisha отдаёт 404).** Пользовательский `PoliteClient.get`
после PR #194 возвращает `None` ровно в одном случае — 404 (остальные отказы поднимают
`SourceUnavailable`). `predict_from_url` превращает `None` в
`RuntimeError("Не удалось загрузить объявление")` → **502 «Не удалось обработать
объявление»**, фронт пишет «Сервис сейчас не отвечает» — вину на себя берёт наш сервис,
хотя объявления просто нет. Бот отвечает «Не получилось оценить объявление: Не удалось
загрузить объявление». Прод-смоук падает, если демо-лот сняли между проходом и смоуком.

## 2. Expected behavior (как должно быть)

- **FR-1 (Must).** WHEN у объявления нет цены, THEN `build_features` SHALL строить
  признаки (цена не признак модели, только таргет обучения), а карточка SHALL
  возвращать оценку с `actual_price = null`, `verdict = null`, `diff_pct = null`.
- **FR-2 (Must).** WHEN krisha отвечает 404 на объявление, THEN пользовательский путь
  SHALL поднимать `ListingNotFound`, а `/api/predict` SHALL отвечать **404** с detail
  «Объявление не найдено — возможно, его уже сняли с продажи».
- **FR-3 (Must).** WHEN фронт получает 404 от `/api/predict`, THEN он SHALL показывать
  detail сервера, а не «Сервис сейчас не отвечает».
- **FR-4 (Must).** Бот SHALL отвечать человеку на снятое объявление понятным текстом и
  SHALL не молчать на любой непредвиденной ошибке оценки.
- **FR-5 (Should).** WHEN прод-смоук получает 404 на демо-лот, THEN он SHALL взять
  другой демо-лот (до 2 раз): снятый лот — состояние источника, а не поломка сервиса.
  Любой другой не-200/не-503 по-прежнему падает сразу.
- **NFR-1.** Обучение не меняется: для числовой цены `pd.to_numeric` — тождество.

### AC

- **AC-1.1.** Given реальная страница с `price=None`; When `predict_from_listing`; Then
  результат есть, `actual_price`, `verdict`, `diff_pct` — `None`, `fair_price` > 0.
- **AC-1.2.** Given `build_features` на числовых ценах; Then `log_price` тот же, что раньше.
- **AC-2.1.** Given `PoliteClient` пользовательского пути и ответ 404; When
  `predict_from_url`; Then `ListingNotFound`.
- **AC-2.2.** Given `/api/predict` и `ListingNotFound`; Then 404, detail про снятое
  объявление; ошибка в негативном кэше (повтор не ходит на krisha 60 с).
- **AC-3.1.** Given фронт и 404 с detail; Then в ошибке — текст detail.
- **AC-4.1.** Given бот и `ListingNotFound`; Then сообщение «не найдено… сняли»; Given
  бот и непредвиденное исключение; Then сообщение об ошибке, а не тишина.
- **AC-5.1.** Given смоук, 404 на первый демо-лот и 200 на второй; Then смоук зелёный.

## 3. Unchanged behavior

- Краулер и sweep: 404 → `None`, как раньше (флаг `raise_on_challenge` у них выключен).
- 502 остаётся для «страница есть, но не разобрали» и внутренних сбоев; 503 — для отказов
  источника (PR #194); 422 — для кривого URL.
- Обучение, признаки для объявлений с ценой, вердикты.

## 4. Root cause

**A.** `np.log1p` вызывается на сырой колонке `price`, не приведённой к числу, — в
отличие от всех числовых фичей рядом (`pd.to_numeric(errors="coerce")`). В обучении
цена всегда числовая, поэтому дыра проявлялась только на пользовательском пути.
**B.** До PR #194 `None` из `get` значил «что угодно пошло не так», и обобщённый 502 был
честнее ничего; после него `None` на пользовательском пути однозначно значит 404, но
вызывающий код этого ещё не различал.

- После выката: снятое объявление в `/api/predict` → 404 с detail; смоук зелёный.
