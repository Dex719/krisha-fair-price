# Telegram-бот и state-файлы

Бот **@fairprice_kzbot** живёт в том же FastAPI-процессе, что и сайт: Telegram присылает апдейты на `POST /tg/webhook`, ответы уходят через Bot API (`bot.tg_call`). Отдельного сервера, polling'а и очереди нет. Без `TELEGRAM_BOT_TOKEN` бот выключен, приложение работает как обычно.

## Webhook

- Регистрация — `bot.setup_webhook()` на старте: `setWebhook(url=<PUBLIC_BASE_URL или https://SPACE_HOST>/tg/webhook, secret_token=webhook_secret(token))`. Публичный адрес: `PUBLIC_BASE_URL` явно, иначе `RAILWAY_PUBLIC_DOMAIN` или `SPACE_HOST` (на HF выставляется автоматически).
- Проверка входящих: заголовок `X-Telegram-Bot-Api-Secret-Token` сравнивается с производным от токена секретом (constant-time), иначе 403.
- Дедуп между двумя воркерами: `update_id` пишется в таблицу `tg_updates` (`INSERT OR IGNORE`); повтор от Telegram или второй воркер — апдейт пропускается.
- Самолечение: `/api/health` не чаще раза в час (`_WEBHOOK_CHECK_INTERVAL_S = 3600`) вызывает `getWebhookInfo`; при `unset`/`mismatch` вебхук перерегистрируется. Статус виден в `health.tg_webhook`, keepalive считает всё, кроме `ok`, деградацией.
- `TG_API_BASE` — подмена базового адреса Bot API (например, Cloudflare Worker `docs/tg-proxy-worker.js`), когда с хостинга api.telegram.org недоступен.

## Команды и поведение (`bot.handle_update`)

| Ввод | Что происходит |
|---|---|
| ссылка на krisha.kz | `predict_gate.cached_predict(url, live_vision=True)` — та же калитка, что у сайта (кэш, single-flight, слоты, лимит); ответ — карточка вердикта с ценой, интервалом, факторами и кнопкой «Открыть в приложении» (Mini App, только в личных чатах) |
| произвольный текст без ссылки | `text_parse.py`: Gemini со строгой JSON-схемой достаёт параметры квартиры → `predict_from_listing`. Без `GEMINI_API_KEY` — подсказка прислать ссылку |
| `/start` | help; с payload `track_<id>` — сразу `/track` на лот (кнопка «Следить за ценой» на сайте), `market_<slug>` — подписка на район со страницы рынка |
| `/help` | короткая справка |
| `/track <ссылка>` / `/untrack <ссылка или id>` | слежка за лотом: алерты при изменении цены и снятии (`tracking.py`, `data/tracked.json`) |
| `/alerts` | текущая подписка на выгодные лоты |
| `/alerts_on [фильтры]` | подписка: число 1–6 или `2к` — комнаты, число ≥7 или `45млн` — потолок цены в млн ₸, слово — район по подстроке (`subscriptions.parse_filters` → `{rooms, max_price, district}`) |
| `/alerts_off` | отписка |

Ответы бота при перегрузке честные: «Сейчас много запросов, попробуй через полминуты» (все слоты заняты) и «Модель ещё не загружена» (Space стартует).

## Что рассылается после ночного рескрейпа (`scripts/send_alerts.py`)

Порядок в одном запуске, каждый шаг fail-soft (ошибка одного не ломает остальные):

1. **Выгодные лоты подписчикам** (`alerts.py`): лоты, впервые увиденные за `ALERT_WINDOW_HOURS = 26` ч (запас к суточному крону), прогоняются через модель; отправляются только `GOOD_DEAL` (цена ниже нижней границы интервала), прошедшие фильтры подписки, максимум `MAX_DEALS_PER_CHAT = 5`, по убыванию выгоды.
2. **Алерты слежки** (`tracking.check_tracked_updates`): для каждого отслеживаемого лота сравнивается цена/статус с последним уведомлённым; снятие сообщается только если лаг `last_seen → delisted_at` ≤ `MAX_TRUSTED_DELIST_LAG_DAYS = 7` — иначе мы не знаем, когда лот реально ушёл.
3. **Топ-5 в канал** (`channel.py`, `TG_CHANNEL_ID`, бот должен быть админом): дайджест лучших `GOOD_DEAL`; чтобы не постить лот дважды, последние `POSTED_KEEP = 500` id хранятся в `data/channel_posted.json`.
4. **Утренний админ-отчёт** (`daily_report.py`, `TG_ADMIN_CHAT_ID`): счётчики прохода из `--summary-json`, размер базы, версия/метрики модели, пользователи за день/неделю/месяц. Вечером — то же по аренде отдельным шагом `rescrape-rent.yml`.
5. По понедельникам (Алматы) — **недельная статистика использования** (`usage.send_weekly_report`); 1-го числа — **месячный отчёт о рынке** (`report.py`) админу и в канал.

Отдельно от рескрейпа: после ретрейна — отчёт `monitoring.py`/`notify_retrain.py` (метрики, дельта, вердикт гейта); при бане krisha — алерт из `rescrape._alert_ban`; при смене состояния прода — `health_check.py` из keepalive; при провале смоука — шаг в `smoke.yml`.

## State-файлы: единственная персистентность без базы

Диск Space стирается при каждом деплое, базы у рантайма фактически нет (она read-only снапшот из релиза). Всё, что должно пережить деплой, лежит **JSON-файлами в репозитории** и коммитится приложением через GitHub Contents API (`subscriptions.save_json_state`). Нужен `GITHUB_PAT` с `contents:write`; без него файлы живут до ближайшего деплоя, а в логах — предупреждение.

| Файл | Кто пишет | Содержимое | Шифрование |
|---|---|---|---|
| `data/subscriptions.json` | бот (`/alerts_on`) | `{chat_id: {rooms, max_price, district, since}}` | да |
| `data/tracked.json` | бот (`/track`), `send_alerts` (последнее уведомлённое состояние) | `{chat_id: {listing_id: {price, title, since}}}` | да |
| `data/channel_posted.json` | `send_alerts` | id опубликованных в канал лотов | нет (нет PII) |
| `data/usage_stats.json` | сервис (`usage.py`), флаш не чаще `FLUSH_INTERVAL = 30 мин`; `USAGE_FLUSH_SYNC=1` — синхронно (тесты/Actions) | события по дням, уникальные — солёные sha256-хэши (10 символов), id не хранятся | нет |
| `data/prediction_log.json` | сервис (`prediction_log.py`), только при `PREDICTION_LOG=1`; в Actions всегда выключено | до `MAX_ROWS = 20 000` записей: лот, цена, оценка, интервал, вердикт, версия модели | нет |

Правила, без которых это ломается:

- **Шифрование** (`subscriptions._fernet`): репозиторий публичный, `chat_id` — PII, поэтому подписки и слежка шифруются целиком Fernet-ключом, выведенным sha256 из `STATE_ENCRYPTION_KEY` (а если её нет — из `TELEGRAM_BOT_TOKEN`). Смена токена без задания `STATE_ENCRYPTION_KEY` = потеря доступа к подпискам.
- **Слияние, не перезапись**: перед PUT файл перечитывается с GitHub и сливается с локальным (`_merge_remote`, с учётом удалённых ключей), потому что писателей несколько — два воркера Space и раннеры Actions. Конфликт (409) → повтор. `STATE_FORCE_OVERWRITE=1` отключает слияние — только для ручного ремонта.
- **Не триггерить деплой**: все пять файлов перечислены в `paths-ignore` у `ci.yml` и `deploy-hf.yml`. Новый state-файл без строки в `paths-ignore` будет пересобирать Space на каждый коммит.
- **Схема** файлов — в докстрингах модулей; менять формат — только с миграцией при чтении (старые записи в репозитории никто не перепишет).

## Локальная отладка бота

Без публичного адреса webhook не зарегистрируется; для локальной проверки достаточно вызвать `bot.handle_update({...})` напрямую или прогнать `tests/test_bot.py` (там фикстуры реальных апдейтов, `tg_call` замокан). Проверить, куда смотрит вебхук прода: `curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getWebhookInfo"`. Описание команд для BotFather — `docs/botfather.md`.
