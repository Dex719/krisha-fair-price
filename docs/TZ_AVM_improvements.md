## Задача 1. Сменить таргет на log(цена за м²)

Сейчас модель, вероятно, предсказывает полную цену. Это плохо: цены растянуты от ~8 млн до
200+ млн ₸, дисперсия растёт с ценой, и ошибка на дорогих объектах доминирует в лоссе.

```python
import numpy as np
from catboost import CatBoostRegressor

df['ppm2'] = df['price'] / df['area']

# выкинуть выбросы (опечатки в цене/площади)
lo, hi = df['ppm2'].quantile([0.01, 0.99])
df = df[df['ppm2'].between(lo, hi)].copy()

y = np.log1p(df['ppm2'])                 # ЦЕЛЬ обучения

model = CatBoostRegressor(loss_function='RMSE', cat_features=cat_cols)
model.fit(X_train, y_train)

# инференс — ОБЯЗАТЕЛЬНО развернуть обратно
pred_ppm2  = np.expm1(model.predict(X_new))
pred_price = pred_ppm2 * X_new['area']
```

Требования:
- `area` **остаётся** в фичах (цена за м² нелинейно зависит от площади: у студий выше, у больших ниже).
- Метрики (MAPE и пр.) считать на **восстановленной полной цене** `pred_price`, не на лог-таргете.
- RMSE на лог-таргете ≈ оптимизация относительной ошибки — это согласовано с MAPE.

## Задача 2. Геопространственные фичи

### 2.1 Цена соседей (KNN) — главная фича

Для каждой квартиры берём K ближайших по координатам объявлений и считаем медианную цену за м².

```python
from sklearn.neighbors import BallTree
import numpy as np

def add_knn_price(train, test, k=10):
    R = 6_371_000.0  # радиус Земли, метры
    tree = BallTree(np.radians(train[['lat', 'lon']].values), metric='haversine')
    ppm2 = train['ppm2'].values

    # TRAIN: первый сосед — сама точка, его выкидываем
    d, i = tree.query(np.radians(train[['lat', 'lon']].values), k=k + 1)
    train['knn_ppm2'] = np.median(ppm2[i[:, 1:]], axis=1)
    train['knn_dist'] = d[:, 1:].mean(axis=1) * R

    # TEST: берём все k соседей из TRAIN (самой точки там нет)
    d, i = tree.query(np.radians(test[['lat', 'lon']].values), k=k)
    test['knn_ppm2'] = np.median(ppm2[i], axis=1)
    test['knn_dist'] = d.mean(axis=1) * R
    return train, test
```

> ⚠️ **УТЕЧКА ТАРГЕТА — главный риск задания.** Дерево соседей строится **только на train**.
> Для train-строк выкидывается первый сосед (это она сама). Нельзя считать KNN по всему датасету
> и потом делать train/test split — это даёт фейково низкий MAPE на валидации и провал в проде.
> При кросс-валидации `knn_ppm2` пересчитывается **внутри каждого фолда** (соседи только из
> train-части фолда).

### 2.2 Расстояния до якорей (в метрах, не бинарно)

```python
R = 6_371_000.0
```

### 2.3 Плотность POI в радиусе

Вместо флага «супермаркет рядом» — **количество** POI каждой категории в радиусе 500 м и 1 км
(супермаркеты, кафе, школы, аптеки, парки). POI бесплатно из OpenStreetMap через Overpass API / osmnx.
Плотность кафе — хороший прокси «живого» района.

### 2.4 Негативные POI (со знаком расстояния)

Существующий флаг «завод рядом» переделать в `dist_factory`, добавить `dist_industrial_zone`,
`dist_railway`, `dist_cemetery`. Эти объекты **снижают** цену — модель должна видеть расстояние,
а не бинарный флаг.

### 2.5 Сырые координаты и район

- `lat`, `lon` подавать как обычные числовые фичи (CatBoost сам нарежет ценовую карту сплитами).

  encoding CatBoost корректно обходит утечку.

## Задача 3. Продуктовая обёртка: «Радар недооценённых»

```python
df['fair_ppm2']  = np.expm1(model.predict(X))
df['fair_price'] = df['fair_ppm2'] * df['area']
df['delta_pct']  = (df['price'] - df['fair_price']) / df['fair_price']
# delta_pct < 0  → дешевле справедливой (недооценено)
undervalued = df.sort_values('delta_pct').head(50)
```

К каждому объекту приложить:
- **Доверительный интервал** — обучить две доп. модели с `loss_function='Quantile:alpha=0.1'`
  и `Quantile:alpha=0.9`, отдавать диапазон цены, а не только точку.
- **SHAP-объяснение** (`model.get_feature_importance(type='ShapValues')`): «дороже на 8% из-за
  этажа и ремонта, дешевле на 5% из-за завода в 600 м». Это превращает оценку в аргумент для торга.

## Протокол оценки (обязательно)

- **Time-based split**, если есть `created_at`: train на старых объявлениях, test на свежих —
  реалистичнее случайного сплита для прода.
- Метрики на восстановленной полной цене: **MAPE**, **MdAPE** (медианная — устойчивее к выбросам),
  доля прогнозов в пределах **±10%**.
- Сравнить с текущим бейзлайном (10% MAPE) на одном и том же holdout.

## Критерии приёмки

1. MAPE на holdout заметно ниже текущих 10%.
2. Нет утечки: KNN и target-encoding считаются только из train (проверить, что метрика на CV ≈
   метрике на отложенном time-split).
3. Генерация фичей вынесена в отдельный воспроизводимый модуль (`features.py`).
4. Работает инференс end-to-end: новое объявление → fair_price + интервал + топ-факторы SHAP.

## Review notes (правки до старта)

Разбор ТЗ + прогон через council (Gemini). Само ТЗ сильное (7/10 «строить с правками»), но до старта
стоит учесть 4 риска, которые оно недооценивает:

1. **Дубли = главная утечка в KNN.** Одна квартира от нескольких риелторов → «сосед» с той же ценой →
   модель списывает ответ у самой себя. **Дедупликация не по id, а по (координаты + площадь + этаж + цена)**
   до обучения — обязательна. Альтернатива/дополнение к KNN — target-encoding по иерархии
   ЖК → микрорайон → район (CatBoost умеет ordered TE из коробки), он чище на дублях.
2. **Лог-смещение при `expm1()`.** Простой `expm1(pred)` даёт смещённую оценку в ₸ (эффект Янсена).
   Нужна bias-коррекция (smearing estimator). В ТЗ этого нет.
3. **Валюта.** Krisha часто хранит цены в $, привязанные к курсу. Без фиксации курса на дату
   публикации таргет зашумлён.
4. **Дрейф рынка + Overpass.** Старые объявления без индексации цен вредят (инфляция тенге) →
   нужна временная фича/дефлятор. Масс-запрос 40k точек в Overpass = риск бана по IP →
   POI-плотность (2.3–2.4) делать в последнюю очередь, начать с `dist_center`/`dist_metro`.

ТЗ (точечная оценка) и идея с conformal-диапазоном/вердиктом (слой неопределённости) **не
конкурируют, а складываются** в один план.
