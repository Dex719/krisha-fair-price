## Три факта, без которых ничего не понятно

1. **Прод не имеет своего диска.** Space на Hugging Face пересобирается при каждом деплое, всё записанное в контейнере стирается. Поэтому база живёт в GitHub Release `db-latest`, модели — в `model-latest`, а «пользовательское состояние» (подписки, слежка, статистика, лог предиктов) — JSON-файлами в самом репозитории, которые приложение коммитит через Contents API. Это не костыль на время, это архитектура.
2. **Весь конвейер — GitHub Actions.** Ночной рескрейп, еженедельный ретрейн с гейтом, деплой после зелёного CI, смоук после деплоя, keepalive раз в 6 часов. Руками ничего не запускается, кроме разовых ремонтов через `workflow_dispatch`.
3. **Сбор вежливый и ограниченный.** Паузы 1.5–4 с между запросами, потолок деталей за проход, `--fail-empty`/`--fail-below` валят ран при подозрительно малом сборе. Любая «оптимизация» скорости упирается в риск бана krisha.kz — см. DATA.md.
