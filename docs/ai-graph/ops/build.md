# Build: Dockerfile, Makefile, dependency locks
purpose: how the prod image is built and how dependencies are pinned.

## Docker image ([[code/Dockerfile]])
- Base `python:3.11.15-slim@sha256:baf8...` (minor + digest pin, issue #119). apt: only `curl` (HEALTHCHECK).
- User `app` uid 1000, WORKDIR `/app`. Note: `/app` itself root-owned → runtime temp files must go inside `models/` or `data/`.
- Layer order: `pyproject.toml README.md requirements-runtime.lock` → `pip install --no-cache-dir --no-deps -r requirements-runtime.lock` → `COPY src` → `pip install -e . --no-deps` (editable so `ROOT_DIR`=/app) → `COPY models data static`.
- ENV `PYTHONUNBUFFERED=1 OMP/OPENBLAS/MKL/NUMEXPR_NUM_THREADS=1`, `WEB_CONCURRENCY=2`. `EXPOSE 7860`.
- `HEALTHCHECK --interval=60s --timeout=35s --start-period=60s --retries=3 CMD curl -fsS --max-time 30 http://localhost:7860/api/health` (generous: /api/health hourly touches Telegram webhook_status, up to 25 s when api.telegram.org unreachable).
- `CMD uvicorn krisha.api.app:app --host 0.0.0.0 --port 7860 --workers ${WEB_CONCURRENCY:-2}`.
- Build context trimmed by [[code/dot-dockerignore]] (`.git .github docs assets infra notebooks reports tests scripts Makefile CHANGELOG.md Dockerfile data/*.db data/*.csv .env ...`). On HF the context is anyway only what [[ops/workflows/deploy-hf]] pushes.
- No DB / weights in image: downloaded at startup ([[concepts/prod-runtime]]).

## Dependency files
| file | what | consumers |
|---|---|---|
| `pyproject.toml` | source of truth, floating `>=`; extras `train` (shap, matplotlib, scikit-learn), `dev` (+pytest, ruff, pytest-playwright, pyyaml) | `make install`, Dependabot |
| `requirements.lock` | `uv pip compile pyproject.toml` (py3.11, x86_64 linux) — full runtime resolve incl. catboost plotting tail | rescrape, rescrape-rent, restore-drill, backfill workflows; CI pip-audit |
| `requirements-train.lock` | `--extra train -c requirements.lock` (shared pkgs same versions) | CI test/e2e, retrain |
| `requirements-runtime.lock` | generated by [[code/scripts/gen_runtime_lock.py]] = requirements.lock minus matplotlib/plotly/graphviz/pillow/contourpy/fonttools/kiwisolver/narwhals… (~100+ MB); install ONLY with `--no-deps` | Dockerfile (prod) |
| `requirements.txt` | legacy floating list for Railway/Railpack | nothing in CI |
Invariant: runtime ⊆ lock ⊆ train with identical versions. [[code/tests/test_runtime_lock.py]] guards. Key pins (2026-11): catboost 1.2.10, fastapi 0.139.0, starlette 1.3.1, uvicorn 0.50.0, pandas 3.0.3, numpy 2.4.6, cryptography 50.0.1, h3 4.5.0, httpx 0.28.1. See [[code/requirements.lock]].

## Makefile ([[code/Makefile]])
`install` (`pip install -e ".[dev]"`), `lock` (3 locks; `UV_FLAGS="--upgrade-package X"` to bump one), `crawl` (5 pages/50), `crawl-full` (300 pages), `crawl-complexes`, `rescrape`, `train`, `api` (uvicorn --reload :8000), `test` (`pytest -q`), `test-e2e` (`pytest -m e2e -q`), `lint` (`ruff check src tests scripts`).

## Dependabot ([[code/dot-github/dependabot.yml]])
Weekly Monday for `pip` (reads pyproject/requirements.txt only — NOT locks) and `github-actions`. Lock CVEs are caught by [[ops/workflows/audit]].

## Gotchas
- Lock compiled for linux even on Windows dev box (else uv adds colorama/tzdata).
- `pip install` runtime lock without `--no-deps` re-pulls matplotlib via catboost Requires-Dist.
- Actions are SHA-pinned (`sha_pinning_required=true` in repo settings since 2026-10-06): checkout v7 `3d3c42e5…`, setup-python v7 `5fda3b95…`, cache v6 `55cc8345…`.
- slim image lacks `/etc/mime.types` → past bug: webp/woff2 served as octet-stream and gzip-compressed (fixed PR #196).
