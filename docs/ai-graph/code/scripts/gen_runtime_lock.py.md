# scripts/gen_runtime_lock.py
purpose: issue #119 — generates `requirements-runtime.lock` from `requirements.lock` minus catboost's plotting tail (catboost declares it mandatory in Requires-Dist, but fit/predict/save/load/get_feature_importance work without it). Prod Dockerfile installs runtime lock with `pip install --no-deps`.
## Key symbols
- `PLOTTING_TAIL` :32 = matplotlib, contourpy, cycler, fonttools, kiwisolver, pillow, pyparsing, graphviz, plotly, narwhals, packaging
- `parse_blocks` :46, `filter_runtime_lock(text)` :67, `main` :72; `HEADER` marks output as autogenerated
## CLI
- none (reads `requirements.lock`, writes `requirements-runtime.lock` at repo root)
## Used by
- `Makefile` `lock` target (regenerate together with `requirements.lock`); referenced in `Dockerfile` comment
- `tests/test_runtime_lock.py` asserts committed runtime lock == generator output → effectively enforced by [[ops/workflows/ci]]
- lock chain `runtime ⊆ requirements.lock ⊆ requirements-train.lock` (spec ci-uses-lock, [[history/kiro-specs]]); [[concepts/ci-pipeline]]
