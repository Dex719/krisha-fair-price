## ⚡ Как это работает

1. Вставляешь ссылку на объявление о продаже квартиры в Алматы — на сайте или в боте (боту можно и просто текст объявления).
2. Сервис скачивает объявление и извлекает ~20 признаков: площадь, комнаты, этаж, возраст дома, район, ЖК, координаты, расстояние до центра…
3. CatBoost-модель считает справедливую рыночную цену и сравнивает с ценой в объявлении.
4. Ответ: вердикт **`ВЫГОДНО` / `В РЫНКЕ` / `ПЕРЕПЛАТА`**, отклонение в %, интервал цены и главные факторы «за» и «против» с пояснениями (SHAP). Бонусом — «похожие уходят за ~N дней», слежка за ценой в один тап и живой дашборд рынка с картой цен.

Для масштаба: наивный бейзлайн «медиана ₸/м² по району × комнатам» даёт MAPE ~16.5% — модель ошибается вдвое меньше. Покрытие интервала цены на тесте ~80% при цели 80%.

**Под капотом:**

- Таргет `log1p(price)`, нативные категориальные признаки (район, микрорайон, ЖК, тип дома) — всего 47 фичей.
- Пространственные признаки: медиана ₸/м² по гексагонам H3 (res 7 и 8), считается только на train и снапшотится в `models/spatial_ref.json` — без утечки теста.
- Интервал цены: MultiQuantile-модель (квантили 10%/90%) с конформной калибровкой (CQR).
- Объяснимость: SHAP-факторы на каждый прогноз + глобальный отчёт [`reports/shap_summary.png`](reports/shap_summary.png).
- Валидация: временно́й holdout (тест — объявления, впервые увиденные за последние 14 дней) с дедупом и purge перевыставлений.

## 🤖 Telegram-бот и Mini App

Тот же сервис — **[@fairprice_kzbot](https://t.me/fairprice_kzbot)**: отправьте ссылку или текст объявления; `/track` — слежка за ценой (алерты при изменении и снятии), `/alerts` — выгодные лоты по фильтрам. Mini App открывает полный интерфейс сайта; сайт связан с ботом deep-link'ами (кнопка «Следить за ценой», подписка на район со страницы рынка).

Бот живёт на том же FastAPI через webhook (`POST /tg/webhook`) — отдельный сервер не нужен. Для своего деплоя достаточно `TELEGRAM_BOT_TOKEN`: webhook регистрируется при старте, health-пинг раз в час чинит его, если слетел.

## 🔁 Данные и надёжность

Конвейер полностью на GitHub Actions, без ручных шагов:

- **Ежедневный рескрейп** — свежие цены, новые объявления, отметки о снятии; вежливые задержки. Ран **падает**, если собрал ноль или подозрительно мало (`--fail-empty`, `--fail-below`) — тихая деградация парсера исключена.
- **База** (SQLite) хранится в GitHub Release с контрольной суммой sha256; Space скачивает и проверяет её при старте. Ежедневные снапшоты с ротацией.
- **Еженедельный ретрейн с гейтом качества**: новая модель заезжает, только если не хуже старой на свежем тесте; гарды временно́й валидности пишутся в мету.
- **Деплой только после зелёного CI**, а смоук ждёт, пока прод поднимется именно на выкаченной ревизии (`/api/health` → `revision`), — «зелёный деплой при лежащем проде» невозможен.
- **Keepalive + health-check** каждые 6 часов: живость, свежесть данных, webhook бота; при деградации — алерт в Telegram.

## 🚀 Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"   # dev включает train-extras (shap, matplotlib)

make crawl        # быстрая проба: ~50 объявлений в data/krisha.db
make crawl-full   # полный обход Алматы (часы — вежливые задержки)
make train        # обучение CatBoost → models/model.cbm + SHAP-отчёт
make api          # http://localhost:8000 — веб-интерфейс + API
make test         # pytest
```

Runtime-деплой (Docker/HF Spaces) ставит только `pip install -e .` — тяжёлые train-зависимости (`shap`, `matplotlib`, `scikit-learn`) вынесены в optional extra `train`: `pip install -e ".[train]"`.

`requirements*.lock` собраны под Linux (CI/Docker); локальная разработка на Windows/macOS — `pip install -e ".[dev]"`. Docker ставит из `requirements.lock`, чтобы prod и Actions не разъезжались на версиях. После правки зависимостей в `pyproject.toml` — `make lock` и закоммить оба лока в том же PR.

Сбор аренды (отдельная база `data/krisha_rent.db`, копится под будущую модель аренды и калькулятор «купить vs снимать»):

```bash
python scripts/rescrape.py --deal arenda --max-new 1000
```

## 🔌 API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/predict` | `{"url": "https://krisha.kz/a/show/..."}` → вердикт, справедливая цена, факторы, срок продажи |
| `GET` | `/api/stats` | срез рынка: районы, ₸/м², распределения цен, тренд по неделям |
| `GET` | `/api/heatmap` | сетка ₸/м² для карты цен (ячейки ~400 м) |
| `GET` | `/api/forecast` | прогноз ₸/м² на 3–6 месяцев (за фича-флагом `FEATURE_FORECAST`, по умолчанию 404) |
| `GET` | `/api/demo` | случайное активное объявление для кнопки «Показать на примере» |
| `GET` | `/api/health` | живость, метрики модели, ревизия деплоя, статус Telegram-webhook |
| `GET` | `/api/metrics` | live-телеметрия: rps, коды ответов, p50/p95/p99, попадания в кэш |
| `POST` | `/tg/webhook` | апдейты Telegram-бота (защищено секретом) |

Страницы: `/` — оценка, `/stats` — рынок Алматы с картой цен, `/about` — как считается оценка.

<details>
<summary><b>Под нагрузкой</b> — расчётный сценарий: ссылку постят в большой телеграм-канал, тысяча человек за две минуты</summary>

- *Горячие ответы* живут в памяти процесса: `/api/health` — 60 с, `/api/stats` и `/api/heatmap` — 10 минут, готовый разбор объявления — 10 минут по id лота. Кэш с single-flight: пересчёт делает один поток, остальные ждут результат; если пересчёт упал — отдаётся последнее удачное значение вместо 503.
- *Статика отдаётся из памяти предсжатой* (`api/static_cache.py`): gzip считается один раз при старте — на локальном замере сжатие на лету стоило половины пропускной способности `/`. ETag от содержимого, `If-None-Match` → 304.
- *Тяжёлый предикт ходит через одну калитку* (`predict_gate.py`) — и веб, и бот: кэш по id лота, single-flight, негативный кэш на битые ссылки, лимит одновременных скрейпов, короткий сетевой бюджет (5 с вместо краулерных 30). Если все слоты заняты дольше `PREDICT_WAIT_S` — честные 503 + `Retry-After` вместо висящего спиннера.
- *Лимиты раздельные*: `/api/demo` не делит бюджет с `/api/predict` — за CGNAT мобильного оператора под одним IP сидит целый город.
- Приложение поднимается в `WEB_CONCURRENCY` процессов (по умолчанию 2). Замер — `python scripts/loadtest.py <url>`, живой прод — `/api/metrics`.

</details>

## 🗂 Структура проекта

```
src/krisha/
├── scraping/       # вежливый HTTP-клиент (задержки, ретраи), парсеры выдачи и деталей, resumable-краулер, рескрейп
├── features.py     # очистка + фичи (этажность, возраст дома, до центра, карты ₸/м²)
├── train.py        # обучение CatBoost, бейзлайн, честная валидация, SHAP
├── predict.py      # ссылка → вердикт
├── factor_hints.py # подсказки к факторам: живые медианы по сегментам базы
├── market.py       # рыночная статистика: срез по районам, срок до снятия
├── bot.py          # Telegram-бот: webhook → predict → ответ; /track, /alerts, deep-link'и с сайта
├── api/            # FastAPI + статичный фронт
└── db.py           # SQLite: схема, upsert по id, история цен
static/             # фронт на дизайн-системе baǵam (design.css): оценка, рынок, о проекте
tests/              # 597 тестов: парсеры (фикстуры с реальной разметкой), фичи, БД, бот, API, фронт-приёмка, train-smoke, артефакты модели
tests/e2e/          # 65 e2e поверх настоящего uvicorn: браузерные (pytest-playwright) + контракт API/статики, из них 3 live-smoke
```

E2e-тесты не входят в `make test` (нужен Chromium): `playwright install chromium`, затем `make test-e2e`. Живой smoke с реальной базой и одним походом на krisha.kz — `pytest -m live` (только вручную).
